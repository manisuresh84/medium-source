Use the Codex Chrome Skill to Document Azure Without Leaving Your Browser

A practical workflow for navigating a signed-in Azure session and turning UI evidence into useful documentation

By Suresh Kumar Mani

2026-08-14

Cloud consoles are excellent at showing what is happening, but turning that live state into clear documentation can be surprisingly tedious. You navigate to the right resource, adjust a filter, open a panel, take a screenshot, crop it, and then repeat the process for every important step.

The Codex Chrome skill can handle much of that browser work while using your existing Chrome session. If Azure is already open and signed in, Codex can navigate the same visible web interface, interact with it, and capture the exact views needed for a guide or troubleshooting record.

The important boundary is simple: you sign in, and Codex works with the resulting browser session. It does not inspect saved passwords, read stored credentials, or bypass authentication.

A simple example: document an Azure resource-health view

Imagine that you need a short operational guide showing engineers how to check whether an Azure resource is healthy. The final document needs only three images:

  1. The resource overview page.
  2. A health or monitoring panel with the relevant time range selected.
  3. A filtered table showing the most useful status rows.

This is a small task, but it demonstrates the complete workflow: navigation, interaction, focused capture, and documentation.

Before you begin

Chrome must have the ChatGPT browser extension enabled under Settings → Computer use. You should also open Azure and complete sign-in yourself, including any multifactor authentication required by your organization.

That separation is a feature, not an inconvenience. Authentication stays under your control, while Codex starts working only after the browser is ready.

Once signed in, give Codex a scoped request such as:

In my existing Chrome session, open the Azure resource named demo-web-app. Capture the Overview page, then open Resource health, select the last 24 hours if that option is available, and capture the status panel. Do not change the resource.

The request identifies the browser, target, desired evidence, and safety boundary. It also avoids a vague instruction like “check Azure,” which leaves too many choices unstated.

What Codex can do in the UI

With the Chrome skill connected, Codex can perform the same visible actions you would normally complete by hand:

  • Navigate through Azure or another web application.
  • Open menus, tabs, panels, and dialogs.
  • Apply filters and choose time ranges.
  • Read visible table and status information.
  • Capture the full page or only the current viewport.
  • Isolate a specific panel, dialog, table, or workflow step for a cleaner image.

This is especially useful when a document needs a sequence of screenshots. Codex can keep the visual state consistent between steps instead of forcing you to rebuild the same filters for every capture.

Prefer focused screenshots over giant pages

A full-page screenshot is useful for orientation, but it is rarely the best image for every step. Azure pages can contain navigation rails, headers, help controls, and large areas unrelated to the point being explained.

For the resource-health guide, use one wide screenshot for context and focused captures for the evidence:

  • Overview: capture enough of the page to establish the resource name and current summary.
  • Health panel: capture the panel heading, selected time range, and status together.
  • Filtered table: capture the column headings and relevant rows, excluding unrelated navigation where possible.

The result is easier to read on Medium, particularly on a phone. A reader should not need to zoom into a desktop-sized screenshot to discover which status matters.

Ask for interaction before capture

Screenshots are most valuable after the UI has been placed in a meaningful state. A strong prompt describes both the interaction and the final view:

Open the monitoring tab, filter severity to Critical and Warning, wait for the table to update, then capture the table and its active filter controls.

This produces evidence that is self-explanatory. The screenshot shows not only the results but also the conditions that produced them.

The same pattern works outside Azure. It can document a deployment dashboard, an internal admin page, a CI result, a support workflow, or a multi-step configuration dialog.

Keep browser automation safe and reviewable

Treat navigation and evidence collection differently from actions that change state. Opening pages, selecting display filters, and taking screenshots are generally read-only. Deleting a resource, changing access, restarting a service, or submitting a configuration form is not.

For documentation work, state the boundary directly:

Navigate and capture only. Do not save changes, submit forms, restart services, or modify permissions.

Also review screenshots before publishing. Cloud interfaces can display subscription IDs, tenant names, email addresses, internal hostnames, IP addresses, or resource naming conventions. Crop, blur, or recapture when a detail is unnecessary for the lesson.

A reusable capture checklist

Before asking Codex to collect a workflow, decide on five things:

  • Target: the exact portal, resource, or page.
  • Starting state: whether you are already signed in and where the browser should begin.
  • Interactions: the tabs, filters, menus, or dialogs to open.
  • Evidence: full-page, viewport, panel, table, or step-by-step screenshots.
  • Boundaries: actions that must not be performed and sensitive details that must not appear.

This checklist turns browser automation into a predictable documentation process instead of an open-ended browsing session.

The practical payoff

The Codex Chrome skill is not just a screenshot shortcut. Its real value is preserving the relationship between an instruction and the visible evidence supporting it. Codex can navigate to a specific state, verify what is on screen, and capture the part that makes the next explanation credible.

For our simple Azure example, that means a concise guide with a clear overview, a meaningful health panel, and a filtered status table—all collected from the browser session you already control.

You remain responsible for signing in and deciding what may be shared. Codex handles the repetitive UI work in between. That division makes browser-assisted documentation both useful and appropriately bounded.
